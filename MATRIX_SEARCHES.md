## What the audit establishes

- [Raw execution ledger](research/combination_search/raw) records actual query strings, calendar year, request status, search date, and returned source titles/URLs. Failed attempts remain in the ledger and are superseded only by executed retries.
- Completed checkpoints may be losslessly compressed as `.jsonl.gz` to conserve disk space. Inspect any batch with `python scripts/record_combination_search.py --batch google iit-bombay`; the reader supports both compressed and plain checkpoints.
- Each company/campus request contains four separate year queries. The search tool returns a shared result pool for the request; a hit is not attributed to all four years.
- A successful search may return no relevant public account. The count establishes query execution, not the existence of an OA or completion of a paper collection.
- [Source review decisions](research/combination_search/reviews) and [initial decisions](research/combination_search/reviews.jsonl) explain selected inclusions and exclusions. Unreviewed URLs remain discovery metadata.
- [Curated reports](data/reports) establish campus, assessment round, year, topic, and difficulty evidence separately. No question statements are retained.
